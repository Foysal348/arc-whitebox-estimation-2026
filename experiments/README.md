# Experiments

Every diagnostic here is built around a *falsifier*: a number that, measured on a real 1024×16 network, either kills an idea
or licenses the next step. The verdict of each one is recorded in `writeup/UNTESTED_IDEAS.md` and, with full method and
numbers, in Part K of `docs/ARC_WhestBench_2026_Complete_Notes.pdf`.

## Working directories

Scripts that need the metered environment (`flopscope`, `whestbench`) are run **from the `whest-starterkit` directory**:

```bash
cd whest-starterkit
python -m uv run python ../experiments/probes/probe_query.py 10,14
```

Scripts that only analyse saved dumps are run **from the repository root**:

```bash
python experiments/probes/probe_isdf.py
```

Each file's docstring states which, and where it writes. Large outputs go to `data/dumps/`.

## probes/ — instrumenting the chain

| Script | Question it answers |
|---|---|
| `probe_query.py`, `probe_query_full.py`, `probe_young_dump.py`, `probe_birth_dump.py` | Dump the chain's internal state (legs, shared basis, birth matrices, thin legs) at chosen layers |
| `probe_rank.py` | Spectra of the source legs and of their Hadamard products (the Khatri–Rao wall) |
| `sens_probe.py`, `probe_d21late.py` | Where the deep content matters: per layer, per birth, and split into the (2,1) slice and the diagonal |
| `probe_query_analyze.py`, `probe_agg.py` | Can the contracted query be surrogated (trace, diagonal, sketch) or pooled into an aggregate state? |
| `probe_columns.py`, `probe_colmask.py` | Birth-column screening: cost saving versus drift, end to end |
| `probe_gem.py` | Is the next layer's contribution predictable from the current slices (slice recursion)? |
| `probe_loopholes.py`, `probe_srccode.py`, `probe_birthcomp.py`, `probe_isdf.py` | Falsifiers for the proposals of consultation rounds 2–4 |
| `probe_adjoint_rank.py`, `probe_adjoint_val.py`, `probe_jac_val.py` | The adjoint / linear-response route, and a validated first-order response model of the chain |
| `probe_aap_mpp.py` | Split of a source's readout into its covariance-path and repeated-index families |
| `probe_tt_rank.py` | TT-cross rank growth of the network function in input coordinates |

## chain/ — runners and analyses

| Script | Purpose |
|---|---|
| `knob_test.py` | Cost, residual time, peak memory and prediction drift of a variant on one local network |
| `pool_census.py` | Where the memory goes: every pooled buffer, grouped |
| `resid_ab.py` | Alternating A/B residual-time comparison of two configurations |
| `run_v29_phase1_256.py` | Run an estimator on the Phase-1 (256×32) public split |
| `residual_fit.py` | Cross-validated study: is the final residual predictable from cheap per-neuron features? |
| `k4_law_fit.py`, `k4_law_fit2.py`, `k4_law_coef.py` | Fit the chain's κ₄ ansatz against a Monte-Carlo teacher and search for a better n²-cheap law |
| `k4_oracle_run.py` | Oracle harness: feed the chain measured κ₄ slices instead of its regenerated ones |
| `make_v31ang.py` | Build the spherical-input variant from a shipped submission |
| `poll_submission.py` | Poll an AIcrowd submission until it grades |

## variants/

Estimator variants generated by patching a shipped submission: the spherical-input chain, the per-row λ variant, the κ₄
oracle build and a float64 build. These are experiment builds; the submitted estimators live in `submissions/`.
